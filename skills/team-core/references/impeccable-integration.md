# Impeccable integration

Impeccable is an optional third-party capability: users install it separately. For an assigned design or UI task where its instructions are available to the active design owner, use the relevant Impeccable guidance unless the user explicitly opts out. The [usage guide](impeccable-usage.md) selects a proportionate workflow; this adapter owns applicability, availability and permission boundaries.

## When to use it

Apply Impeccable to assigned page design, visible UI work, design review, and design-only previews, including a preview that produces no production code. Do not add a separate design workflow for backend-only work, an ordinary bug fix, or incidental cleanup without design intent. A visual adjective such as “bold” or “quiet” does not by itself authorize replacing the established visual world.

The Lead assigns the design owner and phase. The assigned owner reads the active Impeccable Skill and only the references relevant to that work, then follows the supported workflow. Do not make every role repeat the same discovery or critique sequence. A later implementer may reuse an accepted provider-backed brief and say that it reused the brief; it must use Impeccable for additional relevant design work it owns.

## Availability and fallback

- If Impeccable is not installed, use the Kit's normal frontend-design guidance.
- If availability is unknown, the Lead checks the active capability catalog or obtains a trusted, resolved Skill path. Do not infer absence from an unknown result and do not launch software to probe. If availability and access still cannot be established, disclose the uncertainty and obtain the user's direction before doing the affected design provider-free.
- If it is known to be installed but the active role cannot see its instructions, the Lead resolves access before the affected design proceeds. A file, profile, link, or another agent's report does not prove the current role loaded the Skill.
- If access still cannot be established after the Lead resolves it, disclose the gap and obtain the user's direction before doing the affected design without Impeccable. Do not silently skip a known-installed provider.
- If its instructions are accessible but a prescribed launcher, context command, detector, or other engine operation fails, use any provider guidance and supported fallback that remain available. Report which guidance was read and which operation failed or was not run. Do not claim an operation ran or that a detector pass proves visual quality. An engine failure alone does not require user direction when the accessible instructions support a safe fallback.
- An explicit user opt-out overrides Impeccable use for that task; continue with the Kit's normal guidance.

Do not run an Impeccable launcher to probe availability: it may download or bootstrap software. Do not install or update it, bootstrap a runtime, enable hooks, create or repair persistent product/design files, replace brand assets, or upload project material without the user's separate authority. Respect the project's applicable requirements, accepted design decisions, privacy constraints, and assigned file ownership.

## Scope and evidence

For design-only work, return a concrete recommendation or brief; do not write production business code. A prototype is limited to the assigned ownership and must not be mistaken for the integrated product. For implementation, the frontend engineer remains the sole production page/flow owner and uses the frontend-engineering Skill as applicable.

Record provider evidence in the existing work or stage record: whether its instructions were read or an accepted brief was reused, the relevant workflow/reference actually followed, and any access or engine limitation. Do not create a separate report just for this adapter. Keep functional results, rendered visual observations, and user acceptance distinct. Package checks, detector output, and uninspected screenshots do not establish attractiveness, usability, or measured improvement.

See the [pinned-source adapted usage guide](impeccable-usage.md) for intent and workflow selection. The Kit does not install Impeccable; the [official repository](https://github.com/pbakaus/impeccable) and its installation guidance are available for users who choose to install it.
