# 轻量任务协调工具：实施计划

状态：既有 P0–P4 基线的验证记录见[系统设计](task-coordination-design.md)；批准的 execution identity/workspace schema-4 extension 已实现并合回，自动化验证及后续修复证据见本地验收记录 `docs/verification/active/board-execution.md`，历史失败与复测结果分别保留。P5 真实项目试用及用户人工验收待用户选择与执行，macOS／Linux 未验证。本文件负责工作顺序、交付、验证和止损点；先前阶段通过不替代新扩展的验证或人工验收。

## 1. 实施原则

采用可独立验收的小阶段，每阶段先列用例、测试覆盖和人工检查步骤，再开始写实现。沿用现有 stage packet、TDD、独立审查和手工验收状态，不另建验收体系。

当前授权覆盖按阶段开发工具、相应 Skill 接入和隔离测试。开发依赖只在明确的任务范围准备；不因此修改本机全局配置、更新已安装 Kit 或初始化真实项目队列。不提交或发布，除非用户另行要求。本文中的接口在各阶段冻结后才成为实际交付。

实施前重新检查工作区、适用指令、已有实现、文档与 OpenSpec 标记；若已有等价能力，复用并调整文件映射。按现有 Blueprint 规则记录模块与边界；对已有代码的结构性重构单独获得批准。

## 2. 阶段安排

| 阶段 | 依赖 | 拟议负责人 | 交付物 | 退出条件 |
| --- | --- | --- | --- | --- |
| P0 运行时／数据库／实时链路试验 | 用户批准范围 | Lead 串行实现与自检或具名后端 owner；独立 Tester 仅用于实际独立门禁；数据库 Specialist 按需要评审事务／维护 | 固定运行时／驱动、SQLite schema 与事务、备份和最小 SSE 链路 | 平台矩阵、竞争、提交断点、推送空窗与恢复可解释；未知依赖先评审 |
| P1 队列核心与数据生命周期 | P0 结论 | 同一后端 owner；Lead 可串行实现与自检，独立 Tester 按门禁需要 | CLI、schema、图、状态机、幂等、备份／迁移／维护预览 | 核心与维护有真实自动化证据，不丢任务、不误删或制造完成 |
| P2 角色、问询与调度接入 | P1 核心通过 | 文档维护 owner 改规则；后端 owner 改工具；路径不重叠 | 角色授权、资源保留、当前任务收件箱、Lead 与 worker 约定 | 同角色并行、任务范围问询、消息合并受控；保留原权限／验收 |
| P3 实时看板 | P1 一致快照／事件协议；可与 P2 独立部分并行 | 明确页面 owner；按现有设计触发规则安排设计／前端职责 | 本地只读 API、SSE、实时前端、断线与维护状态 | 自动更新、重连一致、旧游标 resync、慢客户端有界、桌面／窄屏可读 |
| P4 完整链路与分发 | P2、P3 | Lead 集成与串行自检；独立 Tester 按门禁需要，Reviewer 独立审查 | 打包／帮助、升级兼容说明、完整工作流证据 | 有界场景闭环；安装测试只使用隔离假 homes |
| P5 真实试用与优化 | P4 通过及用户明确选择试用项目 | Lead 组织，适用角色执行 | 真实任务反馈、已观察成本和缺陷 | 用户评估；不预先承诺速度或 Token 降幅 |

角色是职责，不是固定实例数或强制独立进程。Lead 可串行承担已授权的实现、覆盖计划和自检；只有需要独立证据门禁或有明确并行/上下文收益时才启用独立实例。自检不能替代独立评审/评价。共享 schema、存储协议和最终 CLI 各有一个明确 owner；材料变化后重核受影响覆盖，实质实现保留现有独立 Reviewer 要求。

P0 先实现代表性最小链：最小真实实例登记／授权与资源 fixtures → 批准一个包 → 两进程经同一生产授权／资源规则竞争领取 → owner 提交 → 核验关闭 → 解锁后续任务 → 已提交事件自动到达页面。不能用跳过授权的开关让试验通过。再验证订阅窗口、备份与受控终止恢复；不先铺开全部命令和页面。

## 3. 具体工作包

本表是此功能的拟议实施分解。真正启用 OpenSpec 后需迁入其原生任务并建立 ID 映射，不能同时维护两份实施进度。

| ID | 阶段／依赖 | 输出与边界 | 验证 |
| --- | --- | --- | --- |
| TC-01 | P0／无 | 冻结 schema、事件、权限、来源及最小 Register／Grant／资源约束样例；记录限定修订决定 | 来源／任务／验收区分；无权限绕过；运行时与 SQLite 补丁条件明确 |
| TC-02 | P0／TC-01 | SQLite 事务／备份／最小 SSE 与真实最小授权路径；只用隔离 fixtures | 两进程合法／非法领取、资源竞争、提交断点、恢复、订阅窗口与平台可用性 |
| TC-03 | P1／TC-02 | 跨平台 CLI 与 SQLite 存储；路径、schema、项目绑定、错误码 | 不依赖 PowerShell 运行核心；越界／链接／未知版本／损坏拒绝覆盖 |
| TC-04 | P1／TC-03 | 任务创建、批准、修改、依赖与 Ready 查询 | 循环／缺失依赖、取消上游、版本变化；Ready 查询无模型调用 |
| TC-05 | P1／TC-04 | 核心授权／资源规则及 Claim、Report、Block、Submit、Accept、安全 Release、重开 | 最小登记与授权已可用；CAS、幂等、旧凭据、两类依赖门槛与失效传播；成功的 Report／Block 使用服务器报告时间，回放与其他变更不伪造新报告 |
| TC-06 | P1／TC-03、TC-05 | 一致备份、迁移、完整性诊断、恢复、Archive／Prune／Vacuum 生命周期 | WAL 完整备份；保护引用、幂等／旧请求、空间不足和中断；无自动清空 |
| TC-07 | P2／TC-05 | 扩展完整宿主角色／能力登记、授权集合与资源适配；不是首次实现授权 | 同角色多实例、目录前缀、环境冲突、direct／proxy 适配与实际权限 |
| TC-08 | P2／TC-06、TC-07 | Lead 调度、预授权领取、direct／只读 lead-proxy、安全交回、问询与通知合并；更新规则调用点 | 只读角色不越权、单实例复用、容量拒绝、问询风暴、旧答复、无就绪任务、未知健康度；Status 调度摘要须在分页前按 actor 可见范围计算，不推断 host capacity 或 worker liveness |
| TC-09 | P2／TC-04、TC-08 | Work／OpenSpec 来源引用与显式 Reconcile | 一源多包、来源修订／删除、不可访问证据、新克隆恢复边界 |
| TC-10 | P3／TC-05、P0 事件协议 | 只读 Web 服务／SSE／实时页面，问询与清理占用展示 | 正确游标、断线／重放缺口／慢客户端、Host／访问校验、转义、窄屏与长文本；报告时间与 actor 可见摘要可读，主会话名称刷新不改变任务／授权事实 |
| TC-11 | P4／TC-08、TC-09、TC-10 | package 源码构建为 team-core/runtime，输入／产物 manifest、分发和假 homes 验证；提供独立 runtime 诊断与 opt-in Board 测试入口 | 选定 GitRef 可离线安装已构建产物；不运行其脚本／下载依赖；拒绝源码产物不符，项目数据不被部署操作；默认 Kit setup/test 不增加 Board 依赖 |
| TC-12 | P4／TC-11 | 完整链路、文档与 final diff 审查 | 所有验收有真实证据；未执行／人工待验状态明确 |

已批准的 usability follow-up 沿用 TC-05、TC-08、TC-10 和 TC-11，不新增任务权威或数据库 schema。不同主会话各自绑定 Board，但不共享跨会话文件锁；UI 必须保留现有任务选择、筛选、问询／审批状态与名称同步语义。每阶段的实际用例、执行结果与待验项目仍记录在其 packet，不在计划表里复制运行日志。

若 TC-02 暴露运行时／驱动／SQLite 配置缺陷，停止依赖工作，保留证据，调整驱动或支持矩阵；需本机编译、额外常驻数据库服务或新依赖时先评审，不能退回已被替代的 JSON 主存储或用重试掩盖不可靠提交。

## 4. 预先定义的验收场景

以下为验收场景定义，不是逐项通过声明。实际覆盖分为真实 CLI／SQLite／HTTP、受控故障、渲染／浏览器、协议走查与用户待验；尤其不能用 fixture worker ID 冒充真实宿主 Agent 执行。

| 用例 | 触发与预期结果 | 计划观察层 |
| --- | --- | --- |
| CASE-01 | 同角色两个实例领取不同且无冲突的工作包，各有独立 owner／证据 | 核心＋多进程集成 |
| CASE-02 | 多进程同时领取同一包，只有一次成功；其余得到可解释冲突 | 多进程集成 |
| CASE-03 | 两个包写同一文件、父子目录或独占环境，只允许一个占用 | 资源规则＋集成 |
| CASE-04 | 前置依赖未完成、被取消或丢失，不错误显示就绪 | 图／状态规则 |
| CASE-05 | 只提交代码或测试结果，不绕过独立审查／人工门槛关闭依赖 | 状态／协议集成 |
| CASE-06 | 原领取者交回后重复提交、旧 generation、旧任务版本均被拒绝 | CAS／幂等集成 |
| CASE-07 | 同一操作重试返回原结果；同 ID 不同请求拒绝 | 核心集成 |
| CASE-08 | 在事务提交前后终止，状态／资源／回执／事件全部提交或全部未提交；不出现假成功 | 数据库故障注入／恢复 |
| CASE-09 | 数据库损坏、身份不符或恢复副本不可用，保留现场并拒绝删库重建 | 数据库恢复集成 |
| CASE-10 | worker 运行很久但持续推进，保留分配；失联不自动转交或终止 | 协议走查＋受控宿主演示 |
| CASE-11 | Lead 发现工作量集中，把明确独立部分交给同角色新实例；先冻结再转交原路径 | 协议走查＋受控宿主演示 |
| CASE-12 | 角色不匹配、未授权任务、超出授权版本，领取失败 | 核心协议集成 |
| CASE-13 | 宿主容量拒绝或创建结果未知，不登记假 owner、不默认角色代替 | 模拟宿主集成＋受控宿主演示 |
| CASE-14 | 原任务／OpenSpec 来源修改或删除，相关工作包重新核对，旧验收不被覆盖 | 来源适配集成 |
| CASE-15 | HTML 中出现脚本、长标题或恶意链接，不执行任务文字；可信前端自动显示正确修订 | 浏览器／渲染测试＋实际页面观察 |
| CASE-16 | 初始化已存在队列、未知 schema／链接路径时拒绝覆盖 | 文件系统／兼容测试 |
| CASE-17 | 小任务沿用直接路径；没有就绪任务时子 Agent 交回，不忙循环 | 路由语义走查＋受控宿主演示 |
| CASE-18 | 新克隆／丢失本地队列，依据版本化来源重建候选，不伪造执行／人工验收 | 来源／恢复集成 |
| CASE-19 | Kit 更新或降级不删除目标项目队列；不兼容 schema 明确拒绝 | 隔离安装／降级 |
| CASE-20 | 人与 Agent 看到同一修订；Agent 默认获取有界摘要，详细历史按需读取 | CLI＋快照完整链路 |
| CASE-21 | direct／proxy 实例同时提当前任务问题：去重、紧凑首报、工具提示合并、积压暂停新分配；宿主自动消息另外计量 | 问询并发与 Lead inbox／宿主观察 |
| CASE-22 | 答复修订过期、分配已转交或要求扩大权限，不自动恢复任务／取得批准 | 问询状态与授权集成 |
| CASE-23 | 快照与订阅间有提交、断线后追赶、旧游标／generation 改变，页面仍收敛到正确状态 | SSE／浏览器 E2E |
| CASE-24 | 慢客户端、长时间页面连接、CLI 独立写入，不拖住 SQLite reader／checkpoint 或无限占内存 | 服务集成与资源观察 |
| CASE-25 | 同库归档后数据仍可查；Prune 保护依赖／待答／待验／修复历史／旧请求信息 | 数据维护与恢复 E2E |
| CASE-26 | 活跃 WAL 中做一致备份，恢复到新 generation；不中断任务时复制主文件不算备份 | 备份与迁移集成 |
| CASE-27 | 空间不足、VACUUM 忙／中断／压缩副本失败，原库／最后恢复点保留，不误删 sidecar | 维护故障注入 |
| CASE-28 | 看板服务启停、端口冲突、访问凭据不符，不启动 Agent、不接管未知服务、不改变领取状态 | 服务安全与生命周期 E2E |
| CASE-29 | 只读 Reviewer／Architect 不写 SQLite，通过 Lead 代理记账；真实报告者和代写者可追溯 | 权限适配／受控宿主演示 |
| CASE-30 | writer 冻结提交可解锁测试／审查；未审完不接受实现；退回修改失效受影响证据，无依赖死锁 | 状态与完整调度链路 |
| CASE-31 | 根目录源码与已生成产物不符时交付检查失败；精确 GitRef 安装不执行构建／依赖下载 | 构建／包／假 homes E2E |
| CASE-32 | 上游重开／取消／输入改变使相关 freeze 和传递结果失效；历史保留，不解锁新依赖，不自动终止旧进程 | 图／状态／完整链路 |
| CASE-33 | simulation actor 不接收板、问询或其他案例／评分上下文；仅外层角色记执行事实 | 隔离协议与受控模拟 |
| CASE-34 | Node／驱动缺失只阻止任务板功能，不强制已有直接工作安装；已有队列不可用先安全交接，不另建假空队列 | 可选能力／安装与降级集成 |

依赖计划还需包含：共享读取与独占写入组合、拒绝未声明资源的不实保证、在途进程未结束不能释放、重新打开失败任务保留原修复次数、其他 checkout／clone 冒充注册 workspace 时被拒绝。实际 linked worktree 支持依 schema-4 extension 的登记、资源和 CWD 绑定规则。

协调者接管和队列丢失也必须有负例：普通 worker 不得提升权限；未知在途进程仍阻止资源释放；不能从上游任务列表重新生成领取状态并假称原分配不存在。

补充关键接口断点：dispatch 创建结果 unknown 不盲目重试；Transfer 必须原子失效旧 assignment 并建立新分配；取消但未清理条目在看板可见；正常 OpenSpec checkbox 更新不使整个队列合同失效。

## 5. 测试策略与执行成本

| 覆盖类别 | 决策与理由 |
| --- | --- |
| unit／规则测试 | 必需：图、状态、版本、路径、资源和权限输入验证 |
| integration／CLI contract | 必需：真实 SQLite、多进程竞争、JSON 协议、错误码、问询与 HTTP／SSE |
| E2E | 必需：真实 CLI＋数据库＋浏览器完成领取、问询、核验及自动更新；包含重连与维护恢复链路，与宿主调度证据分开 |
| regression | 必需：受影响 Skill 发现、分发、既有轻量路径和安全移交约定 |
| manual | 必需：人工核对关键边界与看板；用户验收保持独立 |
| UI／可访问性／响应式 | 看板阶段必需：结构、键盘阅读、对比度、窄屏和长文本 |
| security | 必需：路径边界、内容转义、拒绝执行任务文本；不声称同用户强隔离 |
| compatibility／recovery | 必需：运行时／驱动／SQLite 版本、平台文件行为、schema、备份恢复和旧分配；缺环境标记未验证 |
| performance | 条件：按约定规模观察摘要大小、查询与写锁耗时；限值由试验确定 |
| database migration | 必需：备份、事务迁移、外键／完整性检查、不兼容降级、回执与事件保留 |
| visual regression／load | 条件：视觉快照按风险；并发问询、SSE 背压和小型队列负载必测，大规模压力后置 |

确定性状态／并发行为优先 test-first，实际记录 Red／Green；无法可靠自动观察的宿主调度和主观可读性采用有理由的 manual-or-environmental，不伪造 Red 或运行证据。

先跑规则／SQLite／CLI，再跑并发、问询、故障与 SSE 批次；有实际页面后用浏览器验证自动刷新、重连和可读性。分发测试用假 homes，包含无需 PowerShell 的核心入口。没有变动或新风险时不重复全量测试。故障测试只终止自己创建的受控子进程，不结束真实 Agent。

每批记录范围、命令、实际源码／配置输入、估计或 unknown、下一检查点和结果。多进程测试可验证竞争，不等于真实 Agent 已遵循 Skill。跨平台缺少 runner 时如实记录；不能用 Windows 结果宣称 macOS／Linux 已通过。

## 6. 人工核验脚本草案与 E2E 对应

| 人工步骤 | Happy path 预期 | 推荐 edge case | 对应 E2E／其他覆盖 |
| --- | --- | --- | --- |
| 1. 在隔离项目确认队列位置和来源 | 显式初始化，来源可追溯 | 已存在／未知版本／越界路径拒绝 | CASE-16、CASE-18；文件系统测试 |
| 2. 创建两项独立任务和一项依赖任务并批准 | Ready 只显示已具备条件的任务 | 依赖缺失、循环、未批准 | CASE-04、CASE-12；图与 CLI 链路 |

## 7. 资源、清理与回退

测试只写本任务独有的临时根；使用假的项目、Agent 标识和 homes。先保护 Git 忽略范围。每个进程记录自己创建的 PID／路径，仅清理确认为本批创建的对象，验证绝对目标仍在预期目录，finally 清理并检查残留。测试输出留必要的有界证据，不保留安装包、截图堆或完整对话。

真实项目启用是单独的显式动作；不因更新 Kit 自动启用队列。先展示运行时／驱动新增依赖和项目数据保留策略，经批准后启用；首次试用前用一致备份保存队列。启动实时看板只启动明确拥有的本地服务。停用时停止新领取、收尾在途工作并确认写入结束，再回原分配路径；显式停止服务，保留数据库、映射、证据和恢复点，不自动删库。
